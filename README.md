## 4. Правила, которые я выбрала сама (ТЗ оставляет это студенту — пропиши в отчёте)

- **Голодное животное ничего не производит.** Если на складе нет зерна на норму животного — оно в этот ход молока/яиц не даёт.
- **Вместимость** коровника/курятника — 20 животных (`AnimalHouse::CAPACITY`).
- **Цена на рынке** = базовая × (1 − 0,15% × объём продаж за последние 4 хода), но не ниже 30% от базовой. Продажи этого хода влияют на цену со следующего хода (ТЗ: «за прошлый ход»).
- Выручка округляется вниз до целого золота.
- Корм считается **по животному**: животные идут по очереди, каждому зерно либо хватает, либо нет.

## 5. ⚠️ Про баланс (важно!)

С числами из таблицы ТЗ (500 золота, 20 ходов) цель **10 000 золота почти недостижима**: я прогнала 30 000 случайных стратегий — лучшая дала ~4 700 золота (даже при полном отсутствии падения цен — ~5 700). Игра при этом работает правильно, просто цель очень высокая. ТЗ разрешает менять значения («значения можно менять»), поэтому для демонстрации победы можно поставить цель поменьше: в `Game.h`

```cpp
explicit Game(int goalGold = 10000, int maxTurns = 20);
```

замени, например, на `goalGold = 3000`. Либо оставь как есть и на защите скажи, что цель — базовая из ТЗ.

## 6. Чего НЕТ в коде и почему

- **Множественное наследование и виртуальные базовые классы**, **частичная специализация** шаблона: в разделе «Требуемая структура классов» ТЗ их не требует (они только перечислены в цели работы). Закрытое наследование и явная специализация есть.
- «Склады» в ТЗ — «динамические массивы». У меня каждый склад — это объект `Storage<T>`, внутри которого динамический массив (а у фермы отдельно динамический массив производителей).

## 7. Вопросы, которые могут задать на защите

- **Почему `Resource` нельзя создать?** Есть чистая виртуальная `baseCost() = 0` → класс абстрактный → ошибка компиляции.
- **Зачем виртуальный деструктор?** `delete *it` по указателю `Producer*` должен вызвать деструктор настоящего типа (`CowShed` и т. д.).
- **Зачем `clone()`?** Чтобы глубоко скопировать массив `Producer*`, не зная настоящих типов (конструкторов копирования у указателя на базовый класс нет).
- **Зачем правило трёх?** Есть память с `new[]` → без своего конструктора копирования/`operator=` два объекта удалят один и тот же массив (двойное `delete`).
- **Почему шаблон в `.h`?** Компилятор создаёт код шаблона при использовании, поэтому ему нужно видеть тела методов.
- **Зачем специализация `Storage<Gold>`?** Золото — просто число, массив не нужен, интерфейс другой (`spend`).
- **Композиция или наследование для рынка?** Композиция: ферма _содержит_ рынок (has-a), а не _является_ им.
